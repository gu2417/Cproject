## 01 Overview

### 프로젝트 기본 정보

| 항목 | 내용 |
|------|------|
| **프로젝트명 (국문)** | 대학 교직원을 위한 온라인 학생관리 시스템 |
| **프로젝트명 (영문)** | Online Student Management System for University Faculty |
| **버전** | 1.0.0 |
| **기준 문서** | 2026학년도 중간고사 대체 과제 요구사항 |

### 프로젝트 목적 및 범위

• **개발의 필요성**
  - 대학교의 약 9,000명 학생 정보를 중앙 집중식으로 관리
  - 교직원의 행정 업무 효율성 향상
  - 신뢰성 있는 서버-클라이언트 기반 정보관리

• **개발 목표**
  - Windows PC 환경에서 정상 동작하는 C 언어 콘솔 프로그램
  - 사용자 인증 기반 데이터 접근 제어
  - DAEHWAK 구조체 기반 학생정보 관리 및 검색

• **범위 내 기능 (In Scope)**
  - 사용자 인증 (로그인, 회원가입, 로그아웃)
  - 학생 정보 검색 (이름, 학번, 학과별)
  - 학생 정보 CRUD (추가, 조회, 수정, 삭제)
  - 학과별 전체 학생 정보 조회

• **범위 외 기능 (Out of Scope)**
  - GUI 기반 인터페이스
  - 네트워크 암호화 (TLS/SSL)
  - 다중 서버 구조 (싱글 서버만 지원)
  - 모바일 클라이언트

## 02 Features

### 기능 요구사항 분류

| 우선순위 | 기능 | 상세 |
|---------|------|------|
| **P0 (MVP)** | 사용자 인증 | 로그인, 회원가입, 로그아웃 |
| **P0 (MVP)** | 학생 정보 조회 | 학번/이름/학과별 검색 |

### 사용자 인증 (User Authentication)

**요구사항:**
- 사용자는 ID, 암호로 로그인
- 미등록 사용자는 회원가입으로 신규 계정 생성
- 로그인 실패 시 에러 메시지 표시
- 로그아웃 후 서버와의 연결 종료

**입력 데이터:**
- 사용자 ID: ≤ 20자, ASCII 문자만
- 암호: ≤ 32자, 특수문자 포함 가능
- 이름: ≤ 50자, 한글 허용
- 부서: ≤ 50자, 한글 허용

### 학생 정보 검색 (Student Search)

**요구사항:**
- 학번, 이름, 학과로 검색 가능
- 부분 일치 검색 지원
- 검색 결과를 표 형식으로 표시
- 검색 결과가 없으면 "검색 결과 없음" 메시지

**관련 필드:**
- 학생명, 학번, 소속학과, 학년, GPA, 이메일, 모바일폰

### 학생 정보 추가 (Student Add)

**요구사항:**
- 인증된 사용자만 추가 가능
- 중복 학번 체크
- 모든 필드 입력값 검증

**입력 데이터:**
```
학생명(≤50자) | 학번(≤20자) | 학과(≤50자) | 학년(1-4) | 
GPA(0.0-4.5) | 이메일(≤100자) | 모바일폰(≤20자)
```

### 학생 정보 수정 (Student Update)

**요구사항:**
- 인증된 사용자만 수정 가능
- 학번으로 해당 학생 검색
- 각 필드별 개별 수정 지원
- 수정 확인 프롬프트

### 학생 정보 삭제 (Student Delete)

**요구사항:**
- 인증된 사용자만 삭제 가능
- 학번으로 해당 학생 검색
- 삭제 전 확인 프롬프트 필수
- 삭제 완료 메시지 표시

### 학과별 학생 조회 (Department-wise Inquiry)

**요구사항:**
- 학과명으로 해당 학과 모든 학생 조회
- 결과를 표 형식으로 표시
- 페이징 기능 (선택사항)

## 03 Architecture

### 시스템 구성도

```
┌─────────────────────────────────────────────────────────┐
│              클라이언트 (Client Program)                 │
│  ┌─────────────────────────────────────────────────┐   │
│  │  • 로그인 / 회원가입 화면                       │   │
│  │  • 메뉴 기반 사용자 인터페이스                  │   │
│  │  • 입력값 검증 및 서버 통신 (socket)           │   │
│  │  • 응답 처리 및 결과 표시                       │   │
│  └─────────────────────────────────────────────────┘   │
│           메인 루프 (사용자 명령 처리)                  │
└──────────────────────┬──────────────────────────────────┘
                       │ TCP/IP Socket (PORT: 9999)
┌──────────────────────▼──────────────────────────────────┐
│           서버 (Server Program)                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │  • 클라이언트 접속 관리                        │   │
│  │  • 사용자 인증 (users.txt 파일 읽기)          │   │
│  │  • 요청 라우팅 및 처리                         │   │
│  │  • 학생 정보 관리 (연결리스트 + 파일 I/O)     │   │
│  │  • 응답 패킷 생성 및 송신                      │   │
│  └─────────────────────────────────────────────────┘   │
└──────────────────────┬──────────────────────────────────┘
                       │ File I/O
┌──────────────────────▼──────────────────────────────────┐
│              데이터 저장소 (File System)                 │
│  • users.txt (사용자 정보)                             │
│  • SMU_Students.txt (학생 정보)                         │
└──────────────────────────────────────────────────────────┘
```

### 서버 내부 계층 구조

```
────────────────────────────────────────
네트워크 계층 (Network Layer)
  ├─ main.c: listen(), accept()
  └─ client_handler.c: recv 루프, 패킷 수신
────────────────────────────────────────
라우팅 계층 (Routing Layer)
  └─ request_router.c: TYPE 분석 → 핸들러 호출
────────────────────────────────────────
기능 계층 (Business Logic Layer)
  ├─ auth.c: 사용자 인증 (로그인/회원가입)
  ├─ student_search.c: 학생 검색
  ├─ student_add.c: 학생 추가
  ├─ student_delete.c: 학생 삭제
  ├─ student_update.c: 학생 정보 수정
  └─ broadcast.c: 클라이언트에 응답 송신
────────────────────────────────────────
데이터 관리 계층 (Data Management Layer)
  ├─ student_list.c: 연결리스트 관리
  ├─ file_manager.c: 파일 I/O
  └─ user_store.c: 사용자 정보 관리
────────────────────────────────────────
```

### 클라이언트 내부 계층 구조

```
────────────────────────────────────────
메인 루프 (Main Loop)
  └─ main.c: 프로그램 진입점, 메뉴 루프
────────────────────────────────────────
UI 계층 (UI Layer)
  ├─ menu.c: 메뉴 표시 및 사용자 입력
  ├─ screen_login.c: 로그인 화면
  ├─ screen_main.c: 메인 메뉴 화면
  └─ screen_student.c: 학생 정보 관리 화면
────────────────────────────────────────
통신 계층 (Communication Layer)
  ├─ net.c: 서버 연결, 패킷 송수신
  └─ packet_builder.c: 요청 패킷 생성
────────────────────────────────────────
```

### 데이터 흐름 (Data Flow)

**학생 검색 시나리오:**

```
1. 사용자가 "학생 검색" 선택
   ↓
2. 클라이언트가 검색 조건 입력받음 (학번, 이름, 학과)
   ↓
3. 패킷 생성: STUDENT_SEARCH|학번|이름|학과\n
   ↓
4. 서버로 패킷 송신 (socket send)
   ↓
5. 서버 client_handler에서 패킷 수신
   ↓
6. request_router에서 TYPE="STUDENT_SEARCH" 분석
   ↓
7. student_search.c::handle_search() 호출
   ↓
8. 연결리스트에서 조건에 맞는 학생 검색
   ↓
9. 검색 결과 패킷 생성: SEARCH_RES|count|data1;data2;...\n
   ↓
10. 클라이언트로 응답 송신
    ↓
11. 클라이언트 net.c에서 응답 수신
    ↓
12. 검색 결과를 표 형식으로 사용자에게 표시
```

## 05 Security

### 입력값 검증 (Input Validation)

모든 클라이언트 입력은 다음 규칙을 통과해야 함:

| 입력 필드 | 최대 길이 | 허용 문자 | 검증 방법 |
|----------|---------|---------|---------|
| 사용자 ID | 20자 | ASCII (a-z, A-Z, 0-9, `_`) | 정규식 또는 수동 검증 |
| 암호 | 32자 | 모든 printable 문자 | 길이만 검증 |
| 사용자명 | 50자 | 한글, 영문, 숫자 | strlen() 검증 |
| 학생명 | 50자 | 한글, 영문, 숫자 | strlen() 검증 |
| 학번 | 20자 | 숫자, 영문 | 형식 검증 (예: YYYYNNNNN) |
| 학과 | 50자 | 한글, 영문 | strlen() 검증 |
| GPA | - | 부동소수 (0.0~4.5) | float 범위 검증 |
| 이메일 | 100자 | @ 포함한 이메일 형식 | 정규식 검증 |
| 폰번호 | 20자 | 숫자, `-`, `()` | 형식 검증 |

### 사용자 인증 (Authentication)

• **로그인 절차**
  1. 클라이언트가 ID, 암호 전송
  2. 서버가 users.txt에서 해당 ID 검색
  3. 입력된 암호와 저장된 암호 비교 (평문 비교 또는 해시 검증)
  4. 인증 결과를 클라이언트에 응답

• **인증 결과 코드**
  - `0`: 인증 성공
  - `1`: 사용자 ID 불일치
  - `2`: 암호 오류
  - `3`: 이미 접속 중

• **권한 검사**
  - 학생 정보 CRUD 작업은 로그인 상태에서만 가능
  - 각 요청마다 현재 세션 유효성 확인

### 위협 모델 (Threat Model)

| 위협 | 설명 | 완화 방법 |
|------|------|---------|
| **Buffer Overflow** | 입력 문자열이 버퍼 크기 초과 | `strncpy()` 사용, 길이 검증 |
| **Format String** | printf() 등에 사용자 입력 직접 전달 | `printf("%s", user_input)` 사용 |
| **SQL Injection** | SQL 쿼리에 사용자 입력 삽입 (미적용) | Prepared Statement (향후) |
| **암호 평문 저장** | users.txt에 암호를 평문으로 저장 | 해싱 권장 (선택사항) |
| **비정상 종료** | 서버 크래시로 연결 끊김 | 예외 처리 강화, 시그널 핸들링 |

## 06 Database

### 데이터 파일 스키마

#### users.txt (사용자 정보)

**파일 형식**: TAB 구분 텍스트 파일

```
UserID	Password	Department	Name
alice	pass1234	교무처	김교수
bob	pass5678	학생지원팀	이직원
```

**필드 정의**

| 필드명 | 타입 | 길이 | 설명 |
|--------|------|------|------|
| UserID | String | ≤20 | 사용자 ID (로그인용) |
| Password | String | ≤32 | 사용자 암호 (평문 또는 해시) |
| Department | String | ≤50 | 소속 부서명 |
| Name | String | ≤50 | 사용자 이름 |

#### SMU_Students.txt (학생 정보)

**파일 형식**: TAB 구분 텍스트 파일

```
Name	StudentID	Department	Grade	GPA	Email	Phone
김철수	2024001	컴퓨터공학부	2	3.85	kim@email.com	010-1234-5678
이영희	2024002	컴퓨터공학부	2	3.92	lee@email.com	010-2345-6789
```

**필드 정의**

| 필드명 | 타입 | 길이 | 설명 |
|--------|------|------|------|
| Name | String | ≤50 | 학생 이름 |
| StudentID | String | ≤20 | 학번 |
| Department | String | ≤50 | 소속 학과명 |
| Grade | Integer | 1-4 | 학년 |
| GPA | Float | - | 평균학점 (0.0~4.5) |
| Email | String | ≤100 | 이메일 주소 |
| Phone | String | ≤20 | 휴대폰 번호 |

### 연결리스트 자료구조

```c
/* DAEHWAK 구조체 (common/types.h) */
typedef struct DAEHWAK {
    char   student_name[51];      /* 학생 이름 */
    char   student_id[21];        /* 학번 */
    char   department[51];        /* 소속학과 */
    int    grade;                 /* 학년 (1-4) */
    float  gpa;                   /* 평균학점 */
    char   email[101];            /* 이메일 */
    char   phone[21];             /* 휴대폰 */
    struct DAEHWAK *next;         /* 다음 노드 포인터 */
} DAEHWAK;
```

### 메모리 관리

• **초기화**: 서버 시작 시 SMU_Students.txt에서 모든 학생 정보 로드 → 연결리스트 생성
• **추가**: malloc()으로 새 노드 할당, 리스트 끝에 삽입
• **삭제**: 해당 노드 검색 후 링크 재구성, free()로 메모리 해제
• **저장**: 서버 종료 시 또는 매일 01:00에 연결리스트 → 파일 저장

## 07 API

### 패킷 프로토콜 명세

**패킷 형식**: `TYPE|field1|field2|...|content\n`

**최대 크기**: 4096 bytes (UTF-8)

### 인증 관련 패킷

| 메시지 | 방향 | 형식 | 설명 |
|--------|------|------|------|
| LOGIN | C→S | `LOGIN\|<id>\|<password>` | 로그인 요청 |
| LOGIN_RES | S→C | `LOGIN_RES\|<code>\|<id>\|<name>` | 로그인 응답 (code: 0=성공, 1=ID오류, 2=PW오류, 3=중복접속) |
| REGISTER | C→S | `REGISTER\|<id>\|<password>\|<dept>\|<name>` | 회원가입 요청 |
| REGISTER_RES | S→C | `REGISTER_RES\|<code>` | 회원가입 응답 (0=성공, 1=ID중복) |
| LOGOUT | C→S | `LOGOUT` | 로그아웃 요청 |

### 학생 정보 관련 패킷

| 메시지 | 방향 | 형식 | 설명 |
|--------|------|------|------|
| STUDENT_SEARCH | C→S | `STUDENT_SEARCH\|<field>\|<value>` | 학생 검색 |
| STUDENT_SEARCH_RES | S→C | `STUDENT_SEARCH_RES\|<count>\|<data>` | 검색 결과 (data: `field1;field2;...` 세미콜론 구분) |
| STUDENT_ADD | C→S | `STUDENT_ADD\|<name>\|<id>\|<dept>\|<grade>\|<gpa>\|<email>\|<phone>` | 학생 추가 |
| STUDENT_ADD_RES | S→C | `STUDENT_ADD_RES\|<code>` | 추가 결과 (0=성공, 1=학번중복, 2=오류) |
| STUDENT_DELETE | C→S | `STUDENT_DELETE\|<student_id>` | 학생 삭제 |
| STUDENT_DELETE_RES | S→C | `STUDENT_DELETE_RES\|<code>` | 삭제 결과 |
| STUDENT_UPDATE | C→S | `STUDENT_UPDATE\|<student_id>\|<field>\|<value>` | 학생 정보 수정 |
| STUDENT_UPDATE_RES | S→C | `STUDENT_UPDATE_RES\|<code>` | 수정 결과 |
| STUDENT_LIST_BY_DEPT | C→S | `STUDENT_LIST_BY_DEPT\|<department>` | 학과별 조회 |
| STUDENT_LIST_BY_DEPT_RES | S→C | `STUDENT_LIST_BY_DEPT_RES\|<count>\|<data>` | 조회 결과 |

### 응답 코드 (Response Codes)

| 코드 | 의미 |
|------|------|
| `0` | 성공 |
| `1` | 중복 또는 불일치 |
| `2` | 입력값 오류 |
| `3` | 미인증 사용자 |
| `4` | 파일 읽기/쓰기 오류 |
| `5` | 서버 내부 오류 |

## 08 Exception

### 예외 분류

#### 입력값 예외

| 예외 | 원인 | 처리 |
|------|------|------|
| **InvalidIDFormat** | ID에 특수문자 포함 | 에러 메시지 표시 후 재입력 요청 |
| **PasswordTooShort** | 암호가 너무 짧음 | 최소 길이 안내 |
| **StudentIDDuplicate** | 학번 중복 | "이미 존재하는 학번입니다" 메시지 |
| **GPAOutOfRange** | GPA가 0.0~4.5 범위 초과 | 범위 재설정 요청 |

#### 통신 예외

| 예외 | 원인 | 처리 |
|------|------|------|
| **ConnectionFailed** | 서버 연결 불가 | "서버에 연결할 수 없습니다" 메시지 |
| **RecvTimeout** | 응답 수신 시간 초과 | 재시도 또는 연결 종료 |
| **SocketError** | 소켓 에러 | 연결 종료, 에러 로그 |

#### 파일 I/O 예외

| 예외 | 원인 | 처리 |
|------|------|------|
| **FileNotFound** | users.txt 또는 SMU_Students.txt 없음 | 서버 시작 시 새 파일 생성 또는 에러 종료 |
| **FileReadError** | 파일 읽기 실패 | 에러 메시지, 재시도 |
| **FileWriteError** | 파일 쓰기 실패 | 에러 메시지, 저장 대기 |

#### 비정상 종료 (Crash Prevention)

• **SIGPIPE 처리**: 클라이언트 비정상 종료 시 서버 크래시 방지
• **NULL 포인터 검증**: 모든 포인터 역참조 전 NULL 체크
• **메모리 할당 실패**: malloc() 반환값 검증
• **파일 핸들 관리**: 파일 열기 실패 시 처리
